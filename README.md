# Zapisnik

A tool that reads a messy meeting transcript and works out who was there, what was decided, and who has to do what by when.

## Getting started

### Dependencies

Check "requirements.txt" for the required Python packages.

### Environment setup

This script requires an API key from OpenRouter, as well as a model ID. Check ".env.example" for more information.

### Usage

```
python3 zapisnik.py <transcript filename> --out <output directory>
```

## Approach

My approach to this challenge was to use an LLM with a strict system prompt to process the given transcript and extract all required data. The reason I chose this approach is because it's quick and relatively easy to implement programmatically, which was ideal for the short time window I had for this project.

The major flaw of this approach is that the accuracy of the script depends heavily on the quality of the LLM used. For example, the model I initially used, Qwen 3.8 27B, would mess up line numbers all the time and also throw in random gibberish at times. At a few rare occasions, it even hallucinated names. However, switching to NVIDIA Nemotron 3 Ultra 550B immediately shower far better results.

Another issue is that the script cannot work offline because it needs internet access in order to communicate with the GroqCloud servers and interact with LLMs. A RegEx or a lower-level NLP approach would've been far more tedious to plan and implement, but would solve this issue in particular.

### How I used AI assistants

I used ChatGPT to help weigh the pros and cons of different approaches to this problem and ultimately decided to settle for the LLM approach. I also used it later to help me rewrite my system prompt from an extensive and exhaustive but unorganized instruction set into a structured and very strict ruleset for the LLM. Apart from that, I only used official docs (e.g. for `argparse` Python library and GroqCloud's API), online forums (StackOverflow and Reddit) and my own knowledge.

### What I would add with one more week

I would probably look into a more tedious but more consistent NLP approach. Since not everyone is willing to drop money on a stockpile of tokens for an LLM (myself included), a locally-run approach would be much better. Apart from that, I would work on a script for automatic accuracy checking for dates, comparing the meeting transcript and the result generated by the LLM.
